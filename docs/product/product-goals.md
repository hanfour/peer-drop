# PeerDrop 產品目標

狀態：已核可（使用者 2026-09-27）
位階：本文件是產品層的決策準繩，位於 `docs/superpowers/specs/2026-09-14-notes-diary-pivot-design.md`（上位架構規格）之上——架構規格回答「怎麼做」，本文件回答「為什麼做、為誰做、做什麼、不做什麼」。
修改規則：見第 6 節。

---

## 1. 定位

> **PeerDrop 是親近的人之間「慢慢說」的地方——一張紙條、一本輪流寫的日記。沒有動態牆、沒有已讀壓力、沒有追蹤數，內容只有你們看得到。**

### 1.1 核心使用者：近距離親密小圈

- 情侶、閨蜜／死黨、家人、遠距離的朋友。典型圈子 2–6 人（日記本技術上限 12 人，不因定位調整）。
- 不分年齡，但**不特別鎖定青少年**：不為學生族群做校園、班級類功能。
- 他們已經有 LINE／IG，不缺即時溝通；缺的是一個不被訊息洪流淹沒、值得慢慢寫慢慢讀的地方。

### 1.2 痛點

1. 即時通訊裡，重要的話被貼圖與閒聊沖掉，事後也找不回來。
2. 社群平台有觀眾、有數字，說真心話有壓力。
3. 想留下「一起寫的東西」，群組聊天記錄不算數。

### 1.3 價值主張：三支柱

| 支柱 | 意思 | 落在哪個功能 |
|---|---|---|
| **慢** | 一次一張、輪流一人，給內容時間發酵 | 紙條（單封、非對話串）、日記（輪流寫作權） |
| **私** | 只有圈內人看得到，平台也看不到 | 端對端加密、免 Email 匿名帳號、無動態牆與追蹤數 |
| **留** | 寫下的東西會被保存、可以回顧 | 日記時間軸、換機還原、（後置）時空膠囊 |

後置功能以**儀式感**為優先方向——樣式、信封、封面、時空膠囊都是「讓慢有質感」。

## 2. 成功指標

成功的定義是**小而黏的留存**，不是下載量或營收。

### 2.1 北極星：每週「仍在輪轉」的日記本數

定義：過去 7 天內至少有 1 篇 `entry`，**且**過去 28 天內有 ≥ 2 位不同作者寫過的日記本。

它同時反映「慢」（輪流）、「留」（累積）、「小圈」（多人參與）；紙條可以一次性，日記本只有圈子真的在用才轉得下去。

### 2.2 輔助指標

| 指標 | 定義 | 初始目標（假設值，上線 8 週後校準） |
|---|---|---|
| 日記 4 週存活率 | 第 W 週建立的日記本，在第 W+4 週仍有 `entry` | ≥ 30% |
| 輪轉週期中位數 | `pass` 到下一次 `pass` 的間隔 | 1–7 天為健康；> 14 天代表卡住，作為催稿通知的優先依據 |
| 紙條雙向帳號比 | 同一週內既寄出、也收到紙條的帳號比例 | 觀察紙條是有來有往還是單向 |

### 2.3 護欄指標（惡化時先處理，暫停新功能）

- 每千張紙條的檢舉數、封鎖數——匿名功能被濫用的訊號。
- Crash-free sessions ≥ 99.5%（App Store Connect 數據）。

### 2.4 量測原則

1. **只做匯總**：由 operator 手動查詢；不做個人層級報表；不加任何第三方 analytics SDK。
2. **不新增寄收件關係記錄**：紙條雙向帳號比用既有的每日配額計數（`note-quota:s:*`、`note-quota:r:*`）計算，**不記錄誰寄給誰**。
3. 原始計數保留 ≤ 90 天，之後只留匯總數字。
4. **隱私標籤誠實更新**：User ID、Name（暱稱）、用於 App 功能與分析的產品互動資料；不用於追蹤。具體勾選項在上架清單定案。

## 3. 產品原則

任何功能提案先過這五條。**有衝突時，排越前面的越優先。**

1. **私密優先於便利**：會讓伺服器多看到內容或關係的功能，要嘛換做法，要嘛不做。
2. **慢優先於即時**：預設不做已讀回執、正在輸入、在線狀態、拉回式推播；通知只在「輪到你」與「收到東西」時發。
3. **圈內優先於擴散**：不做推薦好友、公開頁、熱門榜、分享到社群的數字；成長只靠圈內邀請（邀請連結、面對面）。
4. **留存靠價值，不靠操弄**：不做連續天數、徽章、FOMO 倒數；催稿通知由圈內成員觸發或只提醒一次，不做無限催。
5. **儀式感優先於功能數**：後置功能照「讓慢有質感」排序；一個做細的信封勝過三個粗糙的新功能。

範例：提議「日記本顯示『X 人正在看』」→ 違反原則 2（即時）與原則 1（暴露行為資料）→ 不做。

### 3.1 非目標（明確不做）

- **陌生人社交**：不做探索、配對、推薦。陌生人**可以**憑 ID 或暱稱寄紙條（維持現況），但產品不推廣（見 4.2）。
- **公開內容**：不做動態牆、公開日記、按讚數排行。
- **廣告**，以及任何形式的追蹤或第三方追蹤 SDK。
- **付費解鎖**：溝通功能與美觀類項目都不收費；營收只來自 tip jar 贊助。
- **取代 LINE／IG**：不做即時群聊、限時動態、貼圖商店。
- **鎖定青少年或校園族群**：不做班級、學校類功能。

## 4. 功能定位與優先順序

### 4.1 各功能的角色

| 功能 | 角色 | 設計取向 |
|---|---|---|
| 交換日記 | **核心**，北極星所在 | 輪流、累積、可回顧 |
| 傳紙條 | **核心**，也是進入點 | 單封獨立紙條，**不做對話串**；最適合把人拉進圈子 |
| 附近／P2P 探索與傳檔 | **圈子的線下入口** | 面對面加好友、面對面邀請進日記本、近距離傳照片 |
| 聊天／語音通話 | 維持現狀 | 只修 bug，不再擴充功能 |

### 4.2 陌生人政策：可以寄，但不推廣

- 收件匣分成「**圈內**」與「**陌生人匣**」。圈內人＝同一本日記的成員、P2P 信任聯絡人、自己寄過署名紙條的對象。**這個判斷只在用戶端本機進行**，伺服器不保存關係資料（原則 1）。
- 匿名紙條無法判斷寄件者是不是圈內人，一律進陌生人匣。
- 「**不接收匿名紙條**」開關：伺服器只存每帳號一個布林值，不需要知道關係。
- 陌生人匣不推播，只在 App 內顯示提示。

### 4.3 優先順序

**P0 上架前（v6 送審阻擋項）**
1. 隱私標籤與 PrivacyInfo（依 2.4）。
2. 依第 1 節定位重寫 App Store 名稱、副標、描述與五語系截圖敘事；README 開頭同步改寫。
3. 實機跨帳號 E2E：iPhone ↔ Mac 互寄紙條、共寫日記。
4. 修正 iOS 既有 8 個失敗測試（`MessageEditDeleteTests`／`Phase2IntegrationTests`）。

**P1 圈子地基**
1. **Apple ID 綁定與換機還原**——沒有它，「留」不成立：換手機等於失去帳號與日記。（由上位規格的「後續」提升至此。）
2. 圈內／陌生人匣分流，以及「不接收匿名紙條」開關（4.2）。
3. 面對面加好友、面對面邀請進日記本（P2P 融入）。

**P2 讓慢有質感**（依序）
1. 紙條樣式與信封
2. 日記封面
3. 催稿通知（成員觸發、每輪一次）
4. 時空膠囊回顧

**P3 其他進階**
- 圖片與短音訊附件（需要新的加密儲存，成本最高）。
- 心情／天氣／背景音樂。
- 閱後即焚：**只限紙條、預設關閉**。它與「留」的支柱有張力，所以不在日記使用、也不作為預設。

## 5. 營收

全部功能免費，沿用既有 tip jar（iOS `tip.small/medium/large`，Mac `com.hanfour.peerdrop.mac.tip.*`）。不以營收作為成功指標；伺服器成本若成為問題，先調整配額與保留期，而不是收費（見 3.1）。

## 6. 使用與維護

### 6.1 功能提案檢查清單

每份新的設計規格（`docs/superpowers/specs/`）開頭都要回答：

1. 服務三支柱（慢／私／留）中的哪一個？
2. 是否違反第 3 節的原則？撞到哪條、怎麼避開？
3. 是否碰到 3.1 的非目標？
4. 預期推動哪個指標（北極星或輔助指標）？

### 6.2 校準時機

- 上線滿 8 週：以實際數據校準 2.2 的目標值（30%、1–7 天）。
- 之後每季檢視一次；北極星連兩季沒有成長，重新審視定位。
- 修改定位、原則或非目標，需要使用者明確核可，並在下方變更紀錄加一行。
