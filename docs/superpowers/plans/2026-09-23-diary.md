# 子專案 3：交換日記 — 實作計畫

> **For agentic workers:** 本計畫由 grok 依任務逐一實作（Claude 派工、審閱）。每個任務有自己的測試循環與審閱關卡；步驟用 `- [ ]` 追蹤。

**Goal:** 端對端加密的多人交換日記：建立／加入（連結與短碼）、伺服器仲裁的輪流書寫（傳遞、建立者跳過）、時間軸／翻頁瀏覽、留言與按讚；iOS 與 Mac。

**Architecture:** 每本一個 `DiaryRoom` Durable Object（key/value）仲裁輪次與只增寫的密文事件；D1 存清單與短碼索引；內容以建立者產生的 `diaryKey`（AES-256-GCM、事件級 AAD）加密；金鑰經邀請連結 fragment 或紙條信封（`kind=diaryKey`）傳遞；客戶端新模組 `PeerDropDiary`，以 `GET /v3/diaries/:id` 為輪次真相、事件 seq upsert。

**Tech Stack:** Cloudflare Worker（TypeScript、DO、D1、KV、vitest）；Swift 5.9 / SwiftUI / CryptoKit；SwiftPM `PeerDropKit`；XcodeGen。

**Spec:** `docs/superpowers/specs/2026-09-23-diary-design.md`（v3，最高權威）

## Global Constraints

- 平台 iOS 16+／macOS 14+；共用視圖在 `PeerDrop/UI/Diary/`，UIKit／AppKit 只能在 `#if os(...)` 內（比照 `AccountSectionView`）。
- 所有日記路由經 `authorizeV3` 且**允許金鑰通道**；所有讀寫（events、report、request-key、get）要求**現任成員**。
- 上限與錯誤碼逐字依規格 §0、§2.1：20 本（409 `diary_limit`）、12 人（409 `diary_full_members`）、64 KB／96 KB／64 MB（413 `too_large`／507 `diary_full`）、5,000／500 scalars（客戶端）、403 `not_member|not_holder|not_owner|skip_self|diary_closed|bad_code`、400 `bad_ref|bad_type|bad_payload`、409 `diary_exists`。
- `since` 不含該序號；`seq` 從 1 起；`POST /events` 成功一律回 `{seq, holderIndex}`（201 新建、200 冪等）。
- 金鑰只有 `openMeta(metaCipher)` 成功才安裝；補發只由成員端 sync 看到 `join` 事件驅動（或 `diaryKeyRequest`，忽略 24h 去重）。
- D1 寫入必須成功才回 2xx（否則 500）；DO 端操作冪等。
- 推播 loc-key：`DIARY_TURN`、`DIARY_ENTRY`、`DIARY_JOIN`、`DIARY_REACTION`；靜默：`diaryKeyRequest`、`diaryKey`（`apns-push-type: background`、priority 5）。
- 深連結 `peerdrop://diary/<id>?code=<code>#k=<key>`：`host == "diary"`；任何 log 不得含 query／fragment。
- 五語字串（en、zh-Hant、zh-Hans、ja、ko）追加進 `PeerDrop/App/Localizable.xcstrings`（不重排、驗 JSON、不新增只差標點的重複鍵）。
- Migration 檔只用整行 `--` 註解、字面值內無分號；wrangler DO migration 下一個 tag 是 `v5`。
- Git：只 `git add <明確路徑>`；commit `type(scope): 描述`＋本文＋`Co-Authored-By: Grok <noreply@x.ai>`；不 push。
- 測試指令：worker `cd cloudflare-worker && npm test -- <pattern>`／`npm test`／`npx tsc --noEmit`；Kit `cd PeerDropKit && swift test --filter <Target>`（不跑 `PeerDropSecurityTests`）；app `xcodebuild build -scheme PeerDrop -destination 'platform=iOS Simulator,name=iPhone 16,OS=latest' -quiet` 與 `xcodebuild build -scheme PeerDropMac -destination 'platform=macOS' -quiet CODE_SIGNING_ALLOWED=NO`，一次只跑一個 xcodebuild。

**驗收（測試案例，全部要有）：**
- 建立：201 回 `{diaryId, inviteCode}`；同 id 同 owner 重送 200 且 `inviteCode` 不變、`metaCipher` 不覆蓋；同 id 不同帳號 409 `diary_exists`；非 26 碼 id 400；第 21 本 409 `diary_limit`；D1 `diary_members` 與 `diary_invites` 各一列。
- 404：未建立的 id 對 `GET /v3/diaries/:id` 回 404（且不建 DO）。
- join：連結 join 與 `POST /v3/diaries/join {inviteCode}` 皆可；碼含小寫／`-`／O／I 經 `normalizeAccountId` 仍成功；錯碼 403 `bad_code`，第 11 次 429；已是成員 200 冪等且 D1 仍有列；第 13 人 409；呼叫者已 20 本 409；closed 403；回應含 `members, holderIndex, ownerAccountId, state, seq, metaCipher`。
- events：非成員 403 `not_member`；非持有者 `entry`/`pass` 403 `not_holder`；`comment`/`like` 任何成員；`like` 同人同篇第二次 200 回既有 seq；`refSeq` 指向非 entry 或不存在 400 `bad_ref`；`join`/`leave`/`meta` 型別 400 `bad_type`；`entry` 缺 payload 400 `bad_payload`；`like` 帶 payload 400；payload 解碼 > 64 KB 413；raw body > 96 KB 413；重複 `eventId` 200 `{seq 相同}` 且 `holderIndex` 不再前進；`pass` 後 `holderIndex` 前進並繞回；`skip`：非 owner 403 `not_owner`、只有 1 人 403 `skip_self`、owner 自己持有時 403 `skip_self`、成功時事件 `skipped` = 被跳過者；`bytesUsed` 累加、達上限 507 `diary_full`、滿後冪等重送仍 200；`since` 不含該筆、分頁 `nextSince`。
- leave：四種索引情境（持有者在中間、持有者在末尾、持有者之前的人離開、owner 兼持有者離開 → owner 轉給 `members[0]`）；最後一人離開 → `state=closed`、不崩潰；closed 後仍可 leave（204）且 D1 列刪除；非成員 leave 204 冪等。
- close：owner 專用；之後 join 與 events 403 `diary_closed`；`GET meta`／`GET events` 仍可。
- invite/reset：owner；舊碼 join 失敗、新碼成功；D1 只剩新碼。
- 成員限定：非成員 `GET /events`、`report`、`request-key` 403。
- report：寫入 `reports(diary_id, diary_seq, sender_hash = senderHash(作者))`，`inbox_item_id` NULL；紙條檢舉仍可寫（`notes-inbox.spec` 既有測試不變）；`GET /v3/admin/reports` 帶出新欄位；配額鍵共用。
- Migration：`applyMigrations` 後 `reports` 允許 `sender_hash` NULL；既有 `notes-*.spec` 全綠。

**驗證指令：** `npm test -- diary` → 全綠；`npm test` 全綠（既有 160 + 新增）；`npx tsc --noEmit`。

### Task 5: Kit — `DiaryStore` 與金鑰補發（`DiaryKeyRelay`、`acceptRelayedKey`、pending）

**Files:** 建 `Sources/PeerDropDiary/{DiaryStore,DiaryKeyRelay}.swift`、`Tests/PeerDropDiaryTests/{DiaryStoreTests,DiaryKeyRelayTests}.swift`。

**Interfaces：**
- `public struct DiaryState { meta: DiaryMeta; events: [DiaryEvent]; isHolder; isOwner; hasKey; pendingKey: Bool }`；`public struct DiarySummary { diaryId; name: String?; memberCount; holderAccountId; isMyTurn }`。
- `@MainActor public final class DiaryStore: ObservableObject { @Published diaries: [DiarySummary]; @Published states: [String: DiaryState]; @Published lastError: String?; init(client: DiaryClient, notesClient: NotesClient, accountManager: AccountManager, crypto: NotesCryptoContext /* 署名 */, keyStore: DiaryKeyStore, directory: URL, encryptor: ChatDataEncryptor, directoryCache: DirectoryCache); init(mock: [DiarySummary], states:); func load(); func syncList() async; func sync(_ id: String) async; func create(name:) async throws -> String; func join(link: URL) async throws -> String; func join(code:) async throws -> String; func leave(_:) async throws; func close(_:) async throws; func writeEntry(_:text:) async throws; func pass(_:) async throws; func skip(_:) async throws; func comment(_:seq:text:) async throws; func like(_:seq:) async throws; func requestKey(_:) async throws; func acceptRelayedKey(_ plaintext: NotePlaintext, sender: NoteSenderState) async -> NotesStore.DiaryKeyDisposition; func report(_:seq:reason:includeText:) async throws; func handlePush(kind: String, diaryId: String) async }`。
