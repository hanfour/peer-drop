## 3. 目標、非目標、反目標

### 目標
1. 全 App（iPhone 與 Mac）換成 MSN 色盤，並建立**兩種底色模式**：`live`（清爽白，用於即時）與 `note`（紙感奶油，用於紙條／離線）。
2. 建立**在線三態**（在線／附近／下線）的資料判斷與視覺（頭像右下角徽章），並在聊天、清單、主頁一致呈現。
3. 導覽改成四分頁：**主頁、紙條、附近、日記**；「已連線」「資料庫」併入主頁；設定移到主頁右上角。
4. **所有現有功能仍可到達**（第 9 節的清單），不因重組而消失。
5. 為專案 C 預留：`note` 模式與「下線」呈現先做好，但在 C 完成前文案要誠實（見 §5.4）。

### 非目標
- 紙條與即時聊天的資料合併、朋友以帳號為準、離線寄紙條：專案 C。
- 頭像照片：專案 D（頭像本階段仍用名字產生，圓角改 16pt）。
- 「更多」分頁與通話分頁：**不做**。設定放主頁齒輪；通話維持在聊天／連線畫面內的按鈕。
- 通訊協定、加密、儲存格式的改動。

### 反目標（做出來卻算失敗的情況）
以下是我的推測，**不是使用者說過的**，請核可時一併檢查：
- 藍色用過頭，整個 App 變回「很科技」：MSN 藍只標記「你的」與「要你動作的」，其餘保持中性。
- 兩種底色切換造成閃爍或使用者迷路：切換要平順，且同一畫面內不同時出現兩種底色。
- 只靠顏色表達狀態（色盲或灰階看不出在線與下線）：每個狀態都要有形狀或文字。
- 因為重組導覽，檔案傳輸、語音通話、群組、QR、中繼連線等功能找不到入口。
- 為了視覺而改了連線、傳輸、聊天的行為。

## 4. 使用者已決定的事

1. **配色**：MSN 色盤（藍為主、綠代表在線、四色蝴蝶當頭像色）。先前選的「蜂蜜黃」不上線；黃色改為「紙條」專用色。
2. **底色**：即時聊天（對方在線）用 B 清爽白底；傳紙條（對方下線）用 A 紙感奶油底。
3. **頭像**：圓角 `16px`。
4. **導覽**：主頁、紙條、附近、日記（參考 WeChat 的「發現」＝我們的「附近」）；主頁版型參考 Kakao「好友」頁。
5. **紙條分頁**＝跟朋友的對話串；現有的遠端紙條要**併進**對話串（專案 C）。
6. **在線的定義**（使用者接受）：在線＝此刻有直連；其餘一律算下線；**不新增**伺服器端在線追蹤。
7. **下線時只能傳文字紙條**（圖片、檔案、語音等對方上線才能傳）；沒有帳號的朋友下線時收不到紙條。
8. 順序 A → B → C → D，本文件含 A 與 B。

## 5. 視覺語彙（專案 A）

### 5.1 色票（起始值）
來源是使用者提供的 MSN 色與草稿。**起始值可為通過對比檢查而調整**，調整後須保持意圖。

| 角色 | 值 | 用途 |
|---|---|---|
| 主色 `brand` | `#0078D7` | 自己的泡泡、送出鈕、未讀徽章、主要按鈕（**白字**，對比約 4.6:1） |
| 亮點 `highlight` | `#00A2E8` | 底部分頁選取的底、「附近」狀態圈；**只用在不放字的地方**（白字只有約 3:1） |
| 在線 `online` | `#80C41C` | 在線徽章（不放字；文字用深色） |
| 紙條 `note` | 填色 `#FFF1CC`、邊 `#F9A825`（虛線）、字 `#4A3200`、徽章 `#F9A825` | 一切「紙條」「對方下線」的標記 |
| 頭像色盤 | `#0078D7`（白字）、`#107C41`（白字）、`#F9A825`（**深色字**）、`#C50F1F`（白字；由 `#E81123` 調深，原值白字僅約 4.4:1） | 依名字穩定選色（沿用已修好的 FNV-1a，見 `PeerAvatarPalette`） |

中性色：
| 角色 | `live`（B，白底） | `note`（A，紙感底） |
|---|---|---|
| 底 | `#F4F9FD` | `#FBF6EE` |
| 分隔線 | `#DDEAF4` | `#EFE4D3` |
| 次要字 | `#5E7387` | `#7D6F5D` |
| 主要字 | `#1E2B36` | `#4A3B2E` |
| 卡片／對方泡泡 | `#FFFFFF` | `#FFFFFF` |

- A（`note`）沿用已合併的 `PaperPalette` 數值（含其夜間暖棕）。
- 夜間的 B（`live`）：我的決定，起始 底 `#0F1720`、面 `#1A2430`、線 `#2A3846`、主要字 `#E6EEF5`、次要字 `#93A4B5`；`brand` 在深色底上可能需要提亮（建置者以對比測試決定）。
- 所有文字組合 ≥ 4.5:1、圖示與圖形物件 ≥ 3:1、輸入框提示字 ≥ 3:1；**四種組合**（`live`／`note` × 淺色／夜間）各自要有測試，沿用 `PaperThemeTests` 的做法（測行為與對比，不釘死色碼）。
- 現有 `PaperPalette`／`PaperTheme` 要演進成**依模式取色**（`live` 或 `note`）；既有 token 名稱與用途保留，避免大規模改名。名稱與結構由建置者決定。

### 5.2 兩種底色模式與切換規則
- **聊天畫面**：對方「在線」＝`live`（白）；對方「下線」＝`note`（紙感）。
- **清單類畫面（主頁、紙條、附近）**：`live`。
- **日記**：`note`（紙感，永遠；它是「慢」的核心）。我的決定，使用者未明說。
- 切換用 250 ms 淡入淡出；**不要**在同一畫面內同時出現兩種底色（導覽列、輸入列、分頁列都跟著畫面的模式走）。
- 連線在聊天中途斷掉：畫面切到 `note`，並出現提示條（§5.4）；重新連上則切回 `live`。

### 5.3 頭像與在線三態
- 圓角：使用者指定 `16px`。我的詮釋：標準列表頭像（約 44 pt 以上）圓角 16 pt；較小的頭像依比例（約 `size × 0.36`）縮小，仍是圓角方形、不變成圓形。
- 徽章在頭像**右下角**，並以底色描邊與頭像分離：

| 狀態 | 條件 | 呈現 |
|---|---|---|
| **在線** | 與該朋友有一條已連線的 `PeerConnection`（`state.isConnected`） | 綠色實心點 |
| **附近** | 出現在 `discoveredPeers` 且尚未連線 | 藍色描邊的空心圈 |
| **下線** | 其餘一律 | 頭像去飽和（變淡）＋右下角黃色圓角方形徽章，內有**信封／紙條圖示** |

- 狀態**不得只靠顏色**：三態形狀不同（實心點／空心圈／方形圖示）；VoiceOver 唸出「在線」「附近，尚未連線」「下線，只能傳紙條」。
- 判斷邏輯要寫成**純函式**（輸入：連線狀態、是否在 `discoveredPeers`；輸出：三態），有單元測試；View 只負責呈現。

### 5.4 下線的聊天畫面（專案 C 之前的誠實版本）
專案 A＋B **不含**離線寄紙條的能力，所以畫面不得宣稱「可以傳紙條」：
- 對方下線：畫面切 `note` 底、頂端提示條寫「**{名字} 下線了，上線後再聊**」，輸入列維持現有的停用狀態；頭像用下線徽章。
- 專案 C 完成時再把提示條改成「現在只能傳紙條」、啟用輸入列、並使用紙條泡泡樣式（`note` 填色、虛線邊、狀態「📮 已寄出」）。紙條泡泡樣式與狀態字串**不在本階段實作**，避免出現無法使用的元件。
- 提示條文案要有五種語言（沿用 `Localizable.xcstrings` 的規則：只用文字插入、`needs_review` 標記、interpolation key 要與 Swift 產生的一致）。

### 5.5 泡泡與其他
- `live` 模式：自己的泡泡 `brand` 白字、對方泡泡白底細邊、全圓角、說話者側下角收小（沿用 6 pt／18 pt 規則）。勾勾狀態語意不變，顏色須在 `brand` 泡泡上達 3:1，且「已送達」與「已讀」一眼可分、不用青色。
- 輸入列、附件選單、橫幅、toast、日期藥丸、空對話等沿用第一階段結構，換成新色票。
- 開關（Toggle）：開啟狀態用 `brand`（Kakao 用黃，我們用藍）。
- 底部分頁：選取＝文字深色加 `highlight` 圓角底（見草稿）；未選取＝次要字色。

## 6. 導覽重組（專案 B）

### 6.1 四個分頁（iPhone）
現況（`PeerDrop/UI/ContentView.swift`）：紙條、日記、附近、已連線、資料庫。改為：

| 新分頁 | 內容 | 來源（現有） |
|---|---|---|
| **主頁** | 見 §6.2 | `ConnectedTab`（本來就有 Active／Contacts 兩段）＋`LibraryTab`（朋友、群組） |
| **紙條** | 對話清單，見 §6.3 | 現有聊天紀錄（`ChatManager` 依對象儲存）＋現有「紙條信箱」 |
| **附近** | 探索與加朋友，見 §6.4 | `NearbyTab`、`ConnectionQRView`、`ManualConnectView`、中繼連線 |
| **日記** | 不變（只換主題） | `DiaryTabContent` |

- 設定：主頁右上角齒輪，開啟既有的 `SettingsView`（目前由 `NearbyTab` 與 `DiscoveryView` 開啟，改為由主頁開啟）。
- iPad：沿用 `TabBarOnlyModifier`（強制分頁列）。

### 6.2 主頁（參考 Kakao 好友頁）
- 粗體大標題「主頁」；右上角：搜尋、加朋友（開啟「附近」的加人流程或直接進入附近分頁）、設定。
- 自己的資料列：頭像（圓角 16）、名稱；點一下進編輯（既有 `UserProfileView`）。
- 「**已連線 N**」區段：目前有直連的朋友（在線），點一下進聊天；顯示連線方式（區域網路／中繼）。
- 「**朋友 N**」區段：原「資料庫」的已存裝置與群組，每列顯示三態徽章與次要字（「已連線」「附近 · 可連線」「上次在線 昨天」「離線」）；附近但未連線的列右側有**填色膠囊「連線」**。
- 最底下一列「邀請朋友加入 PeerDrop」（深色方塊圖示，照 Kakao）：開啟既有的邀請（`RemoteInviteView` 等）流程。
- 群組管理（`GroupDetailView`、`GroupEditorView`、建立群組）從主頁進入。

### 6.3 紙條（本階段只是對話清單）
- 粗體大標題「紙條」；右上角搜尋與新增。
- 一人一列：頭像（含三態徽章）、名字、最後一則預覽、時間、`brand` 未讀徽章。群組列也在這裡。
- **現有的「紙條信箱」要保留入口**：在清單最上方固定一列「紙條信箱（N 張未讀）」，點進去是現有的 `NotesTabContent`（遠端紙條功能在專案 C 之前原封不動）。我的決定。
- 資料來源（對話清單所需的「最後一則訊息、未讀數」）目前是否有現成索引，我沒有查證；建置者需先確認，若沒有就新增一個輕量的清單查詢，**不改儲存格式**。

### 6.4 附近（參考 WeChat「發現」與 Kakao「新增朋友」）
- 粗體大標題「附近」；右上角設定捷徑可省略。
- 最上方一排四個快速入口（圖示＋文字）：**QR 碼**（`ConnectionQRView`）、**手動連線**（`ManualConnectView`，輸入 IP；**不叫「朋友 ID」**，因為以帳號 ID 加朋友是專案 C 才有的功能，現在放會是誤導的空殼）、**邀請連結**（`RemoteInviteView`）、**掃描**。沒有對應功能的入口**不要放**。
- 下方依來源分段：區域網路、藍牙（皆為 `discoveredPeers` 的探索清單，每列右側填色膠囊「連線」）；**「中繼」不是裝置清單**，是「用邀請碼連線」的流程（`RelayConnectView`），所以在附近分頁是一個**入口列**（點了開啟該流程），不是一段清單。沿用既有 `GuidanceCard` 的空狀態與引導。

### 6.5 Mac
現況（`PeerDropMac/Views/MacSidebar.swift`）：側邊欄有 紙條、日記、附近、資料庫、中繼 五段。改為四段：**主頁、紙條、附近、日記**；「中繼」變成「附近」裡的入口列（開啟 `RelayConnectView`，原本是獨立整頁）。聊天仍是獨立視窗（`MacChatWindow`，最小 480×480）。快捷鍵與選單（`PeerDropCommands`）要跟著更新，不得留下指向已移除段落的項目。

## 7. 約束

- **不改通訊協定、加密、儲存格式**。
- 所有新字串五種語言（en、zh-Hant、zh-Hans、ja、ko）；`.xcstrings` 只用文字插入、不可整檔重寫；非繁中標 `needs_review`。
- 無障礙：動態字級到最大仍可讀；VoiceOver 標籤齊全；狀態不只靠顏色（§5.3）。
- 最低版本 iOS 16、macOS 14；`PeerDrop/UI` 由 iOS 與 Mac 兩個 target 共用，iOS 專屬 API 要用 `#if os(iOS)`。
- 新增 Swift 檔後執行 `xcodegen generate`。
- 維持專案慣例：commit 格式、不得 `git commit -a`、不得提交使用者未提交的 `.gitignore` 與 `docs/pet-design/`。

## 8. 驗證

- 單元測試：色票對比（四種組合）、在線三態判斷純函式、既有測試不得失敗。
- **實際畫面**：iPhone 模擬器與實機、Mac；淺色與夜間；`live` 與 `note`；一般與最大字級；各拍一組截圖並與草稿比對（此前的經驗：只看程式碼會漏掉版面問題，例如群組沒套主題、頭像顏色隨機、預覽條被撐大）。
- 用暫時、不提交的測試畫面可以渲染大部分畫面；手勢與真實連線狀態要請使用者在實機確認。

## 9. 功能不得遺失的清單

重組後下列功能必須仍可到達（建置者逐項確認並在 PR 說明列出入口位置）：
即時聊天、傳送檔案、語音通話與 CallKit、斷線與重新連線、信任與同意（`ConsentSheet`）、QR 連線、手動連線（IP）、中繼連線、區域網路與藍牙探索、已存裝置與群組（建立、編輯、指派）、現有遠端紙條（寫、收、封鎖、檢舉）、日記、設定與帳號、打賞（Tip Jar）、邀請朋友。

## 13. 建置者檢查後補充的實作決定（我的判斷，非使用者所說）

這一節是一位沒看過本文件脈絡的建置者讀過文件後提出的問題，我逐一決定如下。使用者核可時請一併檢查。

### 13.1 「朋友」的身分與三態判斷
- 現有資料有四套 id：`DeviceRecord.id`、`DeviceRecord.peerDeviceId`、`connections` 的 key（中繼連線是 `relay-<code>`）與 `peerIdentity.id`、`DiscoveredPeer.id`。**以 `DeviceRecord` 為「朋友」的基準**；三態純函式的輸入是該朋友可能對應的**一組 id**（record id、peerDeviceId、peerIdentity.id），以及「已連線連線的 id 集合」與「探索到的 id 集合」；任一 id 命中即算命中。沿用 `ConnectionManager.connection(for:)` 以 key 與 `peerIdentity.id` 兩種方式查找的做法。
- 「在線」＝命中一條 `state.isConnected` 的連線；**中繼連線算在線**；**傳輸中、通話中算在線**。`.connecting`（建立中）**不算在線**，顯示為「附近」。
- 同一朋友同時有區域網路與中繼兩條連線：主頁「已連線」只顯示**一列**（連線方式寫較優先的那條，區域網路優先）。
- 群組列**不顯示三態徽章**，次要字顯示「N 人在線」。
- 只有手動輸入 IP、從未連上的紀錄：顯示「下線」，次要字「尚未連線過」。
- 若同一台裝置以不同 id 被探索到，可能被當成另一個人：這是既有身分問題，本階段**不解**，在 PR 說明標註；建置者若發現可用 `peerDeviceId` 或憑證指紋低成本對上，可以順手對照，但不得改儲存格式。

### 13.2 紙條分頁的清單資料
- 清單列出：**有 `DeviceRecord` 的朋友中有聊天檔者**，加上**有訊息的群組**（群組訊息存在 `groupMessagesFile`）。沒有對應 `DeviceRecord` 的孤兒聊天檔**本階段不顯示**。
- 「最後一則＋時間＋未讀」目前沒有索引（訊息是依 peerID 一人一檔）：**接受啟動時掃描加記憶體快取**，不改儲存格式；快取要在新訊息、刪除訊息時失效。
- 搜尋範圍：**只搜名字**，不搜訊息內文。

### 13.3 聊天入口與功能入口
- 現況 `ChatView` 只從 `ConnectionView`（已連線詳情頁）進入，下線朋友進不去。**新增一條不依賴 `PeerConnection` 的聊天路由**：從紙條分頁、主頁的朋友列都能對任何朋友開聊天；`ChatView` 本來就能處理「找不到連線」的情況（已有中斷橫幅）。
- 檔案傳輸、語音通話、斷線、中繼資訊等功能維持在 `ConnectionView`（詳情頁）。入口：主頁「已連線」的列、以及聊天畫面標題旁新增一個「資訊」按鈕（只有對方在線時出現）。聊天畫面本身仍保留既有的附件與語音訊息按鈕。
- 在 Mac：點「已連線」或紙條清單的任何一列都開 `MacChatWindow`（獨立視窗），不是 push。

### 13.4 設定與雜項入口
- 主頁齒輪開啟既有 `SettingsView`。`NearbyTab` 現有 toolbar 的其他項目：**傳輸紀錄**（`TransferHistoryView`）移到**設定頁最上方的一列**；手動連線、QR、掃描、中繼各自對應附近分頁的快速入口列。
- 「邀請連結」與主頁底部「邀請朋友加入 PeerDrop」**是同一個流程**（`RemoteInviteView`）。
- 主頁「加朋友」圖示：**切換到附近分頁**（不開 sheet）。
- Mac 沒有 `TabView`：主頁齒輪在 Mac 上**隱藏**，設定沿用 `⌘,` 開啟的 `MacSettingsView`。
- 附近分頁連線成功後：**切到主頁**（原本是切到「已連線」分頁，主頁的「已連線」區段會顯示這條新連線）。
- `ContentView` 的 `selectedTab` 魔術數字（目前：附近 0、已連線 1、資料庫 2、紙條 3、日記 4，散落在 `.openNote`、`.openDiary`、錯誤對話框、`NearbyTab`、推播深連結）：**改成具名的列舉**再重新對應，不得留下指向已移除分頁的數字。

### 13.5 Mac
- `MacSidebarSection` 改為 `home`、`notes`、`nearby`、`diaries`；`PeerDropCommands` 的快捷鍵改為 **⌘⌥1 主頁、⌘⌥2 紙條、⌘⌥3 附近、⌘⌥4 日記**；移除指向「Library」「Relay」的選單項與 `NSLocalizedString`；`MacDetailRouter` 的 `.relay` case 與「Pick Notes, Diaries, Nearby, Library, or Relay」說明文字一併更新。`macSidebarJump` 通知與列舉連動。

### 13.6 `PeerAvatar`
- 圓角、徽章、去飽和做成可選參數（預設不顯示徽章），**呼叫端逐一選用**：聊天、主頁、紙條、附近、朋友列要用；`GroupReadReceiptView` 等其他地方維持現狀。
- 螢幕截圖模式（`ScreenshotModeProvider` 的假對象）：建置者要確認其假的 `DiscoveredPeer`、`DeviceRecord`、連線 id 是否一致，三態才會正確。

## 14. 核可時追加的要求：連線方式可選（專案 E）

使用者核可本文件時追加：**連線方式希望可選——「附近」，以及跟一般通訊軟體一樣「一直連線」**。

### 14.1 這對現有設計的影響
- §4 第 6 項（在線＝此刻有直連、**不追蹤伺服器端在線**）只適用於「附近」模式。「一直連線」模式需要伺服器知道誰在線，與產品目標第 1 條（私密優先、平台看不到關係）衝突，必須另案設計（例如對朋友關係做匿名化、雙方同意後才訂閱在線狀態、可隨時關閉）。
- 「一直連線」還需要：帳號與朋友身分（與專案 C 綁在一起）、推播喚醒（iPhone 不能真的一直連線）、離線訊息投遞。因此列為**專案 E**，建議在 C 之後，或與 C 一起設計。**本文件不設計 E。**

### 14.2 本文件（A＋B）為 E 預留的兩點
1. **三態判斷函式要能加入第三個來源**：除了「直連」與「探索」，之後要能再加入「透過伺服器得知在線」。函式的輸入以「各來源的 id 集合」表示，新增來源不得改既有簽名的語意；A＋B 只接直連與探索。
2. **「連線方式」選單本階段不放。** 在 E 完成前放一個選了也沒有效果的選項，就是空殼。設定頁預留位置即可（不顯示）。

### 14.3 §5.3 的更新
在線三態的定義在 E 之後會變成：在線＝有直連，**或**（使用者選了「一直連線」且朋友經伺服器回報在線）。A＋B 階段維持原定義。
